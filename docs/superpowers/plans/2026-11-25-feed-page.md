# Feed Page UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the placeholder `/feed` with the designed watchlist news feed on mocked data.

**Architecture:** A server component loads the real profile and calls a mock `getFeed()`. One client component, `FeedApp`, holds filter state and composes presentational components. Playwright drives `FeedApp` through a flag-gated `/e2e-feed` page.

**Tech Stack:** Next 16.4 (cacheComponents), React 19, Tailwind 4, Base UI, lucide-react, Vitest + Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-25-feed-page-design.md`

## Global Constraints

- pnpm only. Next here differs from training data: read `node_modules/next/dist/docs/` before using a Next API.
- Theme tokens only (`bg-card`, `bg-secondary`, `bg-background`, `text-muted-foreground`, `text-link`, `bg-primary`, `border`); no hard-coded hex. Dark mode comes from the tokens.
- No text below 11px. Class merging with `cn` from `"cn"`.
- Breakpoints: phone `< md`; sidebar from `md` (768); context panel beside stories from `xl` (1280).
- No horizontal page scroll at 320px or any wider width.
- Pointer cursor is already global; do not add `cursor-pointer`.
- Test hooks use braces so they return nothing (`beforeEach(() => { ... })`).
- Design values (desktop / phone): header 76 / 64px; sidebar 260px; tab bar 66px; h1 28 / 23px bold; headline 15px bold; card radius 14 / 13px; stories column max 680px; context panel 390px; gutter 40px / 20px.

## Review Focus

- 50-ticker watchlist: pills and sidebar stay usable, no sideways page scroll (Task 3, 4, 6).
- Ticker with no known company (`ZZZZ`, `BRK.B`): shows the ticker, no "undefined" (Task 2, 3).
- Profile with no first name: avatar and sidebar still read sensibly (Task 3).
- A ticker + search + time combination that matches nothing, then "Clear filters" (Task 5, 6).
- Ctrl+K on a phone, where search is closed: it opens and takes focus (Task 5, 6).

## Task order

1 → (2, 3, 4 in parallel; disjoint files) → 5 → 6.

### Task 1: Types and coverage tooling

**Files:** Create `src/lib/feed/types.ts`; Modify `package.json`, `vitest.config.mts`, `.gitignore`.

**Interfaces (Produces):**

```ts
export type Company = { ticker: string; name: string | null };
export type Story = {
  id: string;
  ticker: string;
  headline: string;
  publisher: string;
  kind: "news" | "filing";
  /** ISO 8601, UTC. */
  publishedAt: string;
  linkCount: number;
  originalUrl: string;
  isNew: boolean;
};
export type Feed = { companies: Company[]; stories: Story[]; generatedAt: string };
export type TimeRange = "any" | "24h" | "7d" | "30d";
export type FeedFilters = {
  ticker: string | null; // null = All
  time: TimeRange;
  source: string | null; // null = Any source
  query: string;
};
export const NO_FILTERS: FeedFilters = { ticker: null, time: "any", source: null, query: "" };
```

- [ ] Write `types.ts`.
- [ ] `pnpm add -D @vitest/coverage-v8` (same major.minor as installed vitest); add script `"test:coverage": "vitest run --coverage"`; in `vitest.config.mts` add `coverage: { provider: "v8", include: ["src/**/*.{ts,tsx}"], exclude: ["src/**/*.test.*", "src/components/ui/**", "src/app/e2e-*/**"] }`; ignore `/coverage`.
- [ ] `pnpm test` and `pnpm typecheck` pass. Commit.

### Task 2: Mock feed, filtering, formatting

**Files:** Create `src/lib/feed/{get-feed,filter,format}.ts` and a `.test.ts` for each.

**Interfaces (Produces):**
- `getFeed(tickers: string[], now?: Date): Promise<Feed>` — `get-feed.ts`. The seam the backend replaces. No `server-only` import (the e2e page and unit tests call it).
- `filterStories(stories: Story[], companies: Company[], filters: FeedFilters, now: string): Story[]` — `filter.ts`
- `sourcesOf(stories: Story[]): string[]` — `filter.ts`, unique, alphabetical
- `formatPublished(iso: string): string` — `format.ts`, `"24 Nov · 09:42 UTC"`, independent of machine timezone and locale
- `coverageLabel(story: Story): string` — `format.ts`: filing → `"Filed document · original link"`; 1 → `"1 sample link"`; n → `"n sample links grouped"`
- `companyName(ticker: string): string | null` — `format.ts`, from `POPULAR_COMPANIES` in `@/lib/onboarding/companies` with a trailing `" Corporation"` or `" Incorporated"` removed, except `MSFT` → `"Microsoft"`, `NVDA` → `"NVIDIA"`, `AAPL` → `"Apple Inc."`

**Tests (assert):**
- getFeed: `["AAPL","NVDA","MSFT"]` → companies in that order with those names; newest-first; the three newest are AAPL, NVDA, MSFT with the boards' headlines ("Example coverage: company updates its services lineup", "Example coverage: new platform draws data-center interest", "Example filing: quarterly report adds context to company updates"), AAPL `linkCount` 3, NVDA 1, MSFT `kind: "filing"`, publisher `"Company filing"`; others `"Example Publisher"` / `"Example Wire"`.
- Every followed ticker gets at least one story, including `ZZZZ` and `BRK.B` (name `null`); every story's ticker is in the list; ids unique; every url starts `https://example.com/`; `[]` → no stories; 50 tickers → 50+ stories; same input and `now` → equal output.
- Across a three-ticker feed, each time range (`24h`, `7d`, `30d`, `any`) returns a different count, all non-zero.
- filterStories: each filter alone and combined; query is trimmed, case-insensitive, matches headline, ticker, company name, publisher; input order kept; story exactly 24h old is included in `24h`.
- format: fixed strings, run once with `process.env.TZ` changed.

- [ ] Failing tests → fail → implement → pass → report (do not commit; the controller commits).

### Task 3: App chrome (header, sidebar, tab bar, account menu, notice)

**Files:** Create `src/components/feed/{coming-soon,account-menu,app-header,sidebar,tab-bar}.tsx` and a `.test.tsx` for each.

**Interfaces (Produces):**
- `ComingSoonProvider({ children })`; `useComingSoon(): (feature: string) => void`. The provider renders one always-mounted `role="status"` region, fixed above the tab bar on phones, showing `"{feature} is coming soon."` with a "Dismiss" button; auto-hides after 4000 ms; a new call replaces the text and restarts the timer; timer cleared on unmount.
- `AccountMenu({ firstName: string | null, signOutAction: () => void | Promise<void> })` — avatar button `aria-label="Account menu"` showing the first letter upper-cased (a lucide `User` icon if no name), opens a Base UI Popover with the name (`"Your account"` if none) and `<form action={signOutAction}><button type="submit">Sign out</button></form>`.
- `AppHeader({ query: string, onQueryChange: (q: string) => void, firstName, signOutAction })` — `<header>`; wordmark "equitycairn" linking to `/feed`; ONE `<input type="search" aria-label="Search companies, tickers, or stories">` (same placeholder) with a "⌘ K" hint from `md`; ⌘K and Ctrl+K focus it and `preventDefault`; Escape clears and closes. Below `md` the input is hidden until the button `aria-label="Search"` (`aria-expanded`) opens it on a row under the header, focused; toggling closed clears the query; a non-empty query keeps it shown. "Help" button from `md` → `useComingSoon()("Help")`. `AccountMenu` at the end. Header is sticky.
- `Sidebar({ companies: Company[], firstName })` — hidden below `md`, 260px (220px below `lg`), sticky under the header and full remaining height. `<nav aria-label="Main">`: "News feed" link to `/feed` with `aria-current="page"`; "Saved stories" button → notice. "Your watchlist" heading + "Manage" button (`aria-label="Manage watchlist"`) → `"Watchlist management"`. `<ul aria-label="Your watchlist">` with initial marker, ticker, name (omitted if null), scrolling when long. Bottom: avatar initial, first name (`"Your account"` if none), "Personal workspace".
- `TabBar()` — `md:hidden`, fixed to the bottom, 66px plus `env(safe-area-inset-bottom)`; `<nav aria-label="Tabs">`: Feed (link, `aria-current="page"`), Watchlist, Saved (`"Saved stories"`), Profile — buttons → notice with those names. Icons lucide, labelled.

**Tests:** each behaviour above, including no-first-name, null company name, 50 companies, Ctrl+K and ⌘K, Escape, fake-timer auto-hide and restart, sign out calling the action. CSS-only visibility is left to Playwright.

- [ ] Failing tests → fail → implement → pass → report (do not commit).
